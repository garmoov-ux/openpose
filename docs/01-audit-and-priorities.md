# 현황 진단과 우선순위

## 1. 현재 구현 범위

React 19, Three.js, Zustand를 사용하는 단일 페이지 편집기다. FBX 마네킹 또는 절차형 마네킹을 표시하고, 관절 선택, 프리셋, 5가지 표시 모드, 정사각형 PNG 캡처, 2D 관절 JSON 다운로드, 로컬 ComfyUI 이미지 업로드를 제공한다. 화면은 상단 내비게이션, 좌측 480px 패널, 중앙 뷰포트에 의상·테마·소품·문구 생성까지 담고 있다. `src/app/App.tsx`, `src/components/sidebar/LeftUnifiedSidebar.tsx`, `src/core/scene/SceneManager.ts`가 주요 진입점이다.

`README.md`와 `AGENTS.md`의 기능 설명은 현재 코드보다 넓다. 특히 손 21점, 얼굴 랜드마크, COCO 18/25, ComfyUI 프롬프트 큐 실행, 포즈 파일 가져오기는 현재 사용자 흐름으로 완성되지 않았다. 구현 담당자는 이 문서를 현재 코드의 사실과 목표를 나누는 기준으로 사용한다.

## 3. 기능 판단

### 먼저 완성할 것

1. 장면 상태의 직렬화, 재현, 검증. AI와 사람이 같은 데이터를 수정해야 한다.
2. PNG와 키포인트 JSON의 정합성. ControlNet 입력의 신뢰성이 제품의 핵심이다.
3. ComfyUI 업로드와 실제 실행을 분명히 구분한 연동.
4. 선택 대상, 카메라, 포즈의 Undo/Redo와 명시적인 저장/불러오기.
5. Export 작업 상태, 모드별 미리보기, 매핑 오류 진단.

### 줄이거나 제거할 후보

- 기본 편집 흐름에서 의상, 테마, 55종 소품, 대형 프롬프트 조합 패널을 빼고 선택형 고급 작업 공간으로 옮긴다. ControlNet 맵만 추출하는 사용자에게는 선택 비용이 크다.
- `Canny`라는 명칭은 실제 엣지 생성 전까지 제거하거나 `Wireframe`으로 표시한다.
- 근거 없이 `생성 완료`, `OpenPose 표준`, `원클릭`이라고 쓰는 버튼/설명을 수정한다.
- 사용 빈도가 낮은 장식 재질, 중복 저장 화면, 포즈 라이브러리의 과도한 범주는 사용 기록과 목표 워크플로우로 평가한 뒤 축소한다. 기존 자료를 즉시 삭제하지 말고 검색 가능한 별도 데이터로 보관한다.

## 4. 품질 게이트

`npm run build`와 `npm test` 외에 다음 결과가 필요하다. 뷰포트 크기와 내보내기 크기가 다를 때 PNG 관절 중심과 JSON의 좌표 오차가 2px 이내인지 확인한다. 1인/2인, 정면/측면, 카메라 뒤 점, 화면 밖 점, 모델 교체 중 빠른 재선택을 검증한다. WebGL 캡처 50회 후 렌더러 메모리와 브라우저 콘솔을 관찰한다. ComfyUI는 실패 응답, 실행 오류, WebSocket 끊김, 정상 결과를 각각 확인한다.
