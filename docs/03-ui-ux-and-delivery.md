# UI/UX 개편과 구현 단계

## 1. 사용자 작업을 중심으로 한 화면

현재 상단 내비게이션과 좌측 480px 패널은 모델, 229개로 표기된 자세, 의상·소품, 저장·연동을 같은 비중으로 배치한다. 반면 가장 중요한 결과물인 ControlNet 맵과 내보내기는 마지막 패널 안에 있다. 기본 화면을 `장면 만들기 → 자세 조정 → 결과 확인 → 내보내기/연동` 흐름으로 재구성한다. 의상과 소품은 포즈 맵 작업과 별개인 확장 작업 공간으로 옮긴다.

```text
┌────────────────── 상단: 프로젝트 / Undo·Redo / 연결 상태 ──────────────────┐
│ 좌측 240~280px      │             3D 편집 뷰포트            │ 우측 300~340px │
│ 인물 목록           │   선택 대상 및 기즈모                   │ 결과 미리보기   │
│ 모델 / 자세 검색    │   카메라·그리드 간결한 조작             │ 모드 / 크기     │
│ 선택한 관절         │                                       │ PNG/JSON/전송  │
└─────────────────────┴───────────────────────────────────────┴───────────────┘
```

좌측은 편집할 대상을, 중앙은 직접 조작을, 우측은 지금 내보낼 결과를 보여준다. 좁은 화면에서는 좌측과 우측을 순차 패널로 접고 뷰포트는 계속 보이게 한다. 3D 편집은 데스크톱 우선으로 설계하되 768px 이하에서 패널이 뷰포트를 가리지 않게 한다.

## 2. 구체적 상호작용

| 작업 | 개선안 | 완료 기준 |
| --- | --- | --- |
| 관절 선택 | 인물 이름과 관절명을 함께 표시한다. 선택한 관절에만 점·기즈모를 강조하고, 좌우 관절을 트리와 검색으로 찾게 한다. | 2인 장면에서 같은 이름의 관절을 번갈아 선택해도 대상이 바뀌지 않는다. |
| 자세 편집 | 가동 범위 피드백, 대칭 토글, 초기화, Undo/Redo를 관절 편집 근처에 둔다. 단축키는 툴팁과 도움말에 기록한다. | 드래그 1회가 Undo 1단위로 돌아가고 다시 적용된다. |
| 프리셋 | 기본 화면에는 최근/기본/즐겨찾기만 보인다. 전체 라이브러리는 검색과 범주 필터가 있는 드로어에서 연다. | 첫 화면의 선택지가 줄고 특정 자세를 이름으로 찾을 수 있다. |
| 맵 확인 | 우측에 현재 모드의 실제 출력 축소 미리보기와 가로·세로 크기, 포함 인물 수, 키포인트 지원 범위를 표시한다. | 미리보기와 다운로드가 동일 `RenderSpec` 결과를 공유한다. |
| 내보내기 | `PNG 다운로드`, `JSON 다운로드`, `PNG 복사`, `ComfyUI에 업로드`, `워크플로우 실행`을 별도 행동으로 둔다. | 버튼 명칭과 실제 발생한 서버 동작이 일치한다. |
| 오류 | 실패 상태를 해당 버튼 바로 아래에서 설명하고 재시도·설정 열기 중 하나를 제시한다. 상태를 한 줄의 전역 텍스트로 덮어쓰지 않는다. | 실패 시 사용자가 다음 행동을 알 수 있다. |
| AI 제어 | 명령 수신 상태, 마지막 변경 주체, 현재 revision, 수신 오류를 작은 상태 패널로 제공한다. 자동 적용 범위는 세션 단위로 표시한다. | AI 명령 후 사용자가 무엇이 바뀌었는지 알 수 있고 Undo 가능하다. |

확인용 단축키는 `F` 전체 보기, `1/2/3` 정면/측면/상단, `Ctrl+Z` 및 `Ctrl+Shift+Z` Undo/Redo를 제안한다. 실제 키 충돌과 입력 필드 포커스를 검사한 뒤 확정한다. 캔버스에 키보드 포커스와 관절 선택 대체 수단을 제공한다.

## 3. 시각 시스템과 Pretendard

제품 성격은 3D 제작 도구다. 편집 뷰포트와 결과 맵의 색이 판단 기준이므로 UI 색은 차분하게 유지한다. 좌우 패널은 밝은 중성 표면, 뷰포트는 어두운 중성 배경으로 구분한다. 여러 색의 포즈 스켈레톤이 가장 강한 시각 요소가 되게 한다. 제안 토큰: 본문 `#20242B`, 보조 `#65707D`, 패널 `#F7F8FA`, 경계 `#D9DEE5`, 선택 `#2563EB`, 오류 `#B42318`. 이 토큰은 실제 뷰포트 이미지와 함께 대비를 검토해 조정한다.

- **글꼴:** Pretendard Variable을 UI 전역의 기본 글꼴로 사용한다. 현재 CSS는 jsDelivr의 Pretendard 정적 CSS를 불러오면서 `Pretendard Variable`을 먼저 요청한다. 제공 파일의 실제 `font-family` 이름을 확인하고 일치시킨다. 오프라인 사용을 위해 라이선스를 확인한 뒤 `public/fonts/`에 WOFF2를 두고 `@font-face`로 로드한다. `font-display: swap`과 시스템 글꼴 폴백을 유지한다.
- **크기:** 기본 본문 14px/21px, 주요 액션 14px/20px, 패널 제목 16px/24px, 미세 정보 최소 12px/18px. 현재 `text-[10px]`, `text-[11px]`이 상태·설명에 널리 쓰이므로 실제 작업 정보는 12px 이상으로 올린다.
- **버튼:** 주 행동은 화면마다 하나를 강조한다. 캡처/다운로드/전송은 기능 이름으로 구분하고 상태만 아이콘과 색으로 보조한다. 모든 버튼에 포커스 링, 40px 이상의 클릭 영역, `disabled` 이유를 제공한다.
- **동작:** 패널 전환과 작업 완료 피드백에만 짧은 전환을 사용한다. `prefers-reduced-motion`을 존중한다. 렌더 루프와 React 상태를 분리한다.

## 4. 화면 컴포넌트 제안

`EditorShell`은 패널 배치만 맡고, `ActorPanel`은 인물/관절 목록, `PoseLibraryDrawer`는 프리셋 검색, `ViewportCanvas`는 캔버스, `OutputInspector`는 맵 미리보기와 출력 정보, `ExportActions`는 다운로드·복사, `ComfyWorkflowPanel`은 연결·매핑·실행을 맡는다. 현재 `ExportPanel.tsx`의 태그 요약과 ComfyUI 상태를 분리한다. 테마·의상·소품 컴포넌트는 `AppearanceWorkspace`에서 지연 로드한다. `TopNavBar`, `LeftUnifiedSidebar`, `SidebarQuickOptionsBar`에 중복된 모드·섹션 전환은 한 군데로 합친다.

새 컴포넌트는 `.tsx` 300행, 엔진 `.ts` 350행, 함수 80행 한도를 지킨다. 현재 `SceneManager.ts`는 346행으로 한도에 가깝다. 캡처, 모델 전환, 선택, ComfyUI 흐름을 새 모듈로 분리한 뒤 UI 개편을 진행한다.

## 5. 단계별 전달 계획

### 단계 0: 명칭과 실패 표시 바로잡기

- `Canny`를 임시 `와이어프레임`으로 표시하고, ComfyUI 버튼을 `이미지 업로드`로 바꾼다.
- 클립보드·업로드 실패를 작업 근처에 표시한다.
- 완료: 사용자에게 실제로 실행되지 않은 생성 작업을 완료라고 알리지 않는다.

### 단계 1: 데이터와 캡처 정확도

- `SceneDocumentV1`, actor ID, 명령 적용기, 공통 `RenderSpec`을 구현한다.
- COCO 18 출력과 다중 인물 정책, PNG/JSON 좌표 일치를 구현한다.
- 완료: 골든 파일과 브라우저 캡처 테스트가 `02-engine-and-api-design.md`의 기준을 통과한다.

### 단계 2: 기본 편집 UI

- 좌측 인물/자세, 중앙 편집, 우측 실제 출력 미리보기로 구조를 바꾼다.
- Undo/Redo, 선택 대상 표시, 검색 가능한 프리셋, Pretendard 로컬 제공을 적용한다.
- 완료: 신규 사용자가 기본 자세를 선택하고 1024px OpenPose PNG와 JSON을 같은 카메라로 추출할 수 있다.

### 단계 3: ComfyUI 실행

- API 형식 워크플로우 가져오기, LoadImage node ID 지정, 업로드/큐/결과 추적을 구현한다.
- 완료: 정상 생성과 실패/중단/재연결을 구분해 보여준다. 연결하지 않아도 로컬 내보내기는 동작한다.

### 단계 4: AI API 브리지

- 내부 명령 계약에 로컬 브리지를 연결한다. AI가 장면 조회, 관절 명령, 렌더 작업, 결과 조회를 할 수 있게 한다.
- 완료: 외부 명령 1건과 명령 묶음이 동일한 UI 조작 결과를 만들고 revision·Undo가 일관되게 동작한다.

## 6. 검토 시나리오

1. 빈 장면에서 모델을 추가하고 프리셋을 적용한다. 관절을 드래그하고 되돌린 후 다시 적용한다.
2. 2인 장면에서 파트너의 오른팔을 선택한다. 메인 모델의 오른팔에 기즈모가 붙지 않는다.
3. 넓은 뷰포트에서 1024×1024 및 768×1024로 내보낸다. PNG와 JSON 위치를 비교한다.
4. ComfyUI가 꺼져 있을 때 업로드 실패 원인과 다음 행동이 나온다. 서버가 켜져 있을 때 업로드와 워크플로우 실행이 서로 다른 상태로 표시된다.
5. 인터넷이 끊긴 로컬 환경에서 Pretendard가 로드되고 기본 편집이 동작한다.

## 7. 범위 판단 메모

의상·테마·소품은 기본 포즈 편집 화면의 선택 부담을 줄이기 위해 별도 작업 공간으로 둔다. 의상은 사용자의 추가 요구에 따라 [조합형 의상 시스템](04-wardrobe-audit-and-implementation.md)과 [품목 카탈로그](05-wardrobe-catalog.md)로 확장한다. 실제 의상 메쉬는 Depth·Normal·Lineart 맵에 반영되므로 출력 옵션과 연동한다. 방 가구·소품은 사용 사례에 따라 별도 패널에서 관리한다.
